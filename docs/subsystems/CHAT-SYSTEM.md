# **VTT‑Chat: Message Flow, Privacy, and Visibility Design Document**

## **1. Overview**

The VTT‑Chat system supports five primary message types — **IC**, **OOC**, **Whisper**, **System**, and **Greenroom** — each with specific visibility, retention, and styling rules. The core principle is **experience persistence**: players retain all messages they have witnessed in a session, even if they move between groups. Messages are never "lost" as players transition contexts.

This document defines:

- Message types and persistence rules
- Session vs. campaign history boundaries
- Visibility model (what players see when they're present)
- Retention and archival rules
- UI tagging and styling
- Filtering model for unified chronological flow
- Spectator ephemeral model

---

## **2. Message Types**

### **2.1 In‑Character (IC)**

- Sent within a specific group context (e.g., "Party A", "Tavern").
- **Visibility (current session):** visible to all group members present in that group at time of send, plus DM.
- **Persistence:** persisted to campaign history (retained permanently).
- **Group movement:** if a player moves groups mid-session, they retain all IC messages witnessed in their group history.

### **2.2 Out‑of‑Character (OOC)**

- Sent to a group context (local OOC) or globally (if DM enables global OOC).
- **Visibility (current session):** local OOC visible to group members; global OOC visible to all players and spectators.
- **Persistence:** persisted to campaign history.
- **Group movement:** retained in player history regardless of group transitions.

### **2.3 Whisper**

- **Whisper to player:** visible only to sender, target(s), and DM.
- **Whisper to DM:** always allowed.
- **Player–player whispers:** can be disabled by DM campaign setting.
- **Persistence:** persisted to campaign history (sender and all targets always see it, even across group moves).
- **Visibility across group moves:** DM whispers to a player remain visible regardless of which group the player joins (except inside Whisper Group context).

### **2.4 System Messages**

- Generated by the system (conditions applied, environment changed, player joins/leaves, etc.).
- **Scope:** can be group-scoped or global.
- **Persistence:** persisted to campaign history.
- **Spectator visibility:** spectators see global system messages only (not group-specific events).

### **2.5 Greenroom Messages**

- Sent during greenroom staging (pre-session or between sessions).
- **Visibility (staging):** visible to players/DM in greenroom only.
- **Persistence:** ephemeral — persisted until next CLEANUP action, then purged.
- **Allowed types:** general OOC messages and system bookends only (no IC/Whisper).

### **2.6 Whisper Group Messages**

- Sent within a temporary private sanctuary created by the DM.
- **Visibility:** visible only to DM and players currently in Whisper Group.
- **Persistence:** **deleted on Whisper Group exit**. DM can configure campaign setting to persist or delete on session end.
- **Recording:** not recorded or logged during Whisper Group (off-the-record).

---

## **3. Special Case: Whisper Group**

A temporary, private sanctuary.

### **Rules**

- Only players/DM inside the Whisper Group can see/send messages.
- Messages **disappear** once the Whisper Group ends.
- No logs retained.
- DM may suppress all other chat streams while inside (campaign toggle).
- Whisper Group messages are not IC/OOC; they are **ephemeral private messages**.

## **4. Visibility Model**

### **4.1 Core Principle**

> A user sees only the messages that were visible to them **at the time they were in the same context** (group, whisper group, greenroom).

This requires:

- **Per‑user context timeline**
- **Filtering based on (message.context ∩ user.contextHistory)**

## **3. Session vs. Campaign History**

### **3.1 Session Scope**

- A session is a contiguous play period (e.g., "2026-05-12 Evening Game").
- During a session, all non-ephemeral messages are stored in volatile memory and broadcast via WebSocket.
- Session messages are visible to all connected players in real-time.

### **3.2 Campaign History**

- Campaign history is the persistent archive of all messages across all sessions for a campaign.
- **Persisted messages:** IC, OOC, Whisper, System, and Greenroom messages survive to campaign history.
- **Ephemeral messages:** Whisper Group messages deleted on exit (unless DM campaign setting persists them).
- Messages are searchable and retrievable in a History panel.

### **3.3 Session Boundaries**

When a new session starts:

- Fresh session state: no IC/OOC/Whisper/System/Greenroom messages initially.
- Prior session messages available in History panel (searchable, read-only).
- DM can manually archive or export prior session as campaign record.
- Spectators see **current session only** — no access to campaign history.

## **4. Visibility Model: Experience Persistence**

### **4.1 Core Principle**

> **Players retain all messages they have directly experienced in a session, regardless of subsequent group movements.** Visibility is determined by presence and context at time of send, but once experienced, messages persist in the player's session history and campaign archive.

This means:

- **No trapped messages:** if a player was in Group A when Alice said something, they always remember it, even if they move to Group B later.
- **Spectators are different:** spectators have session-only ephemeral visibility; they do NOT retain messages in campaign history.
- **DM sees everything:** all messages in all contexts, always.

### **4.2 Real-Time Visibility (During Session)**

For each message, determine visibility at send time:

| Message Type             | Visible To (In Real-Time)                             |
| ------------------------ | ----------------------------------------------------- |
| **IC in Group A**        | Group A members, DM                                   |
| **OOC (local)**          | Group members, DM                                     |
| **OOC (global)**         | All players, spectators, DM                           |
| **Whisper**              | Sender, target(s), DM                                 |
| **System (group-bound)** | Group members, DM (spectators see only global system) |
| **System (global)**      | All players, spectators, DM                           |
| **Greenroom**            | Greenroom occupants, DM                               |
| **Whisper Group**        | Whisper Group occupants, DM                           |

### **4.3 Message Retention (Archived)**

Once sent, messages are retained as follows:

| Message Type      | Persisted           | Archive                             | Notes                                                                 |
| ----------------- | ------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| **IC**            | Yes                 | Campaign history                    | Available in all future sessions                                      |
| **OOC**           | Yes                 | Campaign history                    | Available in all future sessions                                      |
| **Whisper**       | Yes                 | Campaign history (sender + targets) | Private messages retained permanently                                 |
| **System**        | Yes                 | Campaign history                    | Serves as timeline markers                                            |
| **Greenroom**     | Yes (until CLEANUP) | Not archived                        | Purged at session cleanup or pre-session CLEANUP                      |
| **Whisper Group** | No (default)        | Not archived                        | Deleted on Whisper Group exit; DM can toggle persistence per campaign |

### **4.4 Per-Message Metadata**

Each message stores:

| Field          | Type           | Purpose                                           |
| -------------- | -------------- | ------------------------------------------------- |
| `id`           | string         | Unique identifier                                 |
| `timestamp`    | number         | Global chronological ordering                     |
| `sessionId`    | string         | Which session this message belongs to             |
| `campaignId`   | string         | Which campaign archive (for history lookup)       |
| `senderId`     | string         | Player or DM ID                                   |
| `type`         | enum           | IC, OOC, Whisper, System, Greenroom, WhisperGroup |
| `groupId`      | string \| null | Group, Greenroom, or WhisperGroup ID              |
| `targets`      | string[]       | For whispers: array of recipient IDs              |
| `isPersistent` | boolean        | Does this message survive session end?            |
| `isEphemeral`  | boolean        | For Whisper Group: marked for deletion on exit    |
| `styleTag`     | string         | UI styling hint                                   |
| `payload`      | string         | Message content (markdown-safe)                   |

## **5. Unified Message Stream & Filtering**

### **5.1 Default View: Unified Chronological Stream**

The chat UI displays **all messages a player has experienced in the current session**, in one unified chronological stream. This includes IC, OOC, Whisper, System, and Greenroom messages in their natural temporal order.

### **5.2 Real-Time Filtering Algorithm**

For each message `m` in the current session:

- **DM:** sees all messages.
- **Spectators:** see IC, OOC, and global system only; never see whispers, greenroom, or whisper group.
- **Players:** use the algorithm below, where `user.sessionGroupHistory` is the set of all groups they've been in this session.

```text
if m.type == 'IC':
  show iff (m.groupId in user.sessionGroupHistory)

else if m.type == 'OOC':
  if globalOOC is enabled: show(m)
  else show iff (m.groupId in user.sessionGroupHistory)

else if m.type == 'Whisper':
  show iff (m.senderId == user.id or user.id in m.targets)

else if m.type == 'System':
  show iff (m.isGlobal or m.groupId in user.sessionGroupHistory)

else if m.type == 'Greenroom':
  show iff (user.currentContext == 'Greenroom')

else if m.type == 'WhisperGroup':
  show iff (user.currentContext == 'WhisperGroup')

else:
  hide(m)
```

**Key:** `user.sessionGroupHistory` never clears during a session. Once a player visits a group, all messages from that group remain visible. This ensures **no trapped messages**.

### **5.3 Optional Filtering & Search (UI Convenience)**

Players can optionally filter the unified stream:

- **By group:** Show only IC/OOC from "Party A"
- **By type:** Show only IC, only OOC, only Whispers
- **By sender:** Show only messages from specific players
- **Search:** Full-text search across all visible messages

Filtering is a UX enhancement and does **not override privacy rules**. Spectators never see whispers or greenroom, regardless of filter settings.

### **5.4 Greenroom Message Fade**

When leaving Greenroom context:

- Greenroom messages fade to 30% opacity
- Slide down and collapse
- Removed from DOM (but retained in campaign history)

### **5.5 Whisper Group Message Deletion**

On Whisper Group exit:

- Messages marked `isEphemeral: true` are **deleted immediately**.
- They do **not** persist to campaign history (unless DM campaign setting enables persistence).
- This is intentional off-the-record behavior.
- Default: delete. DM can toggle per campaign.

## **6. Styling & Tagging**

### **6.1 Goals**

- Clear message type identification
- Minimal clutter
- Accessible at a glance
- Works in light/dark themes

### **6.2 Suggested Style Tags**

| Type          | Tag                 | Visual                            |
| ------------- | ------------------- | --------------------------------- |
| IC            | `ic-msg`            | Subtle parchment tint, serif font |
| OOC           | `ooc-msg`           | Grey bubble, sans-serif           |
| Whisper       | `whisper-msg`       | Soft purple, lock icon            |
| System        | `system-msg`        | Gold or blue, italic, small icon  |
| Greenroom     | `greenroom-msg`     | Teal, translucent                 |
| Whisper Group | `whisper-group-msg` | Dark purple, ephemeral fade       |

### **6.3 Required UI Elements**

- **Sender name**
- **Group tag** (IC/OOC/Whisper/Greenroom)
- **Visibility icon** (lock, globe, group)
- **Timestamp**
- **Ephemeral fade animation** for Whisper Group messages

## **7. Spectator Rules**

Spectators in a session have **ephemeral, session-only visibility**:

**Spectators can see:**

- IC messages (from active/visible groups)
- OOC messages (local and global)
- Global system messages

**Spectators cannot see:**

- Private whispers
- Whisper Group messages
- Greenroom messages
- Group-bound system messages

**Spectator History:**

- Spectators do **NOT** have access to campaign history panel.
- Spectator messages are **not** persisted to campaign archive.
- On session end, spectator view is cleared.
- If a spectator rejoins a later session, they see only that session (no cross-session history).

---

## **8. DM Controls**

DM can toggle (campaign-scoped settings):

- **Global OOC visibility** — make OOC visible to all players or keep it group-scoped.
- **Player–player whispers** — enable or disable whispers between players.
- **Whisper Group persistence** — toggle whether Whisper Group messages are deleted or archived.
- **Suppress other chat streams in Whisper Group** — when active, players see only Whisper Group messages (for immersion control).

DM always sees:

- All IC messages
- All OOC messages
- All whispers (to anyone)
- All system messages
- All greenroom messages (while in greenroom)
- All Whisper Group messages (while in group)

## **9. Data Structures**

### **9.1 Message Object**

```ts
interface ChatMessage {
  id: string
  timestamp: number

  // Session & campaign context
  sessionId: string
  campaignId: string

  // Sender & recipients
  senderId: string
  type: 'IC' | 'OOC' | 'Whisper' | 'System' | 'Greenroom' | 'WhisperGroup'
  targets?: string[] // For whispers

  // Context & scope
  groupId?: string | null // Group, Greenroom, or WhisperGroup ID
  isGlobal?: boolean // For System: broadcast to all

  // Persistence & lifecycle
  isPersistent: boolean // Survives session end?
  isEphemeral?: boolean // For WhisperGroup: auto-delete on exit?

  // UI & styling
  styleTag: string // 'ic-msg', 'ooc-msg', 'whisper-msg', etc.

  // Content
  payload: string // Message text (markdown-safe)
  createdAt: Date
  updatedAt?: Date
}
```

### **9.2 User Session Context**

```ts
interface UserSessionContext {
  userId: string
  sessionId: string

  // Current state
  currentGroupId?: string | null
  currentContextType: 'GROUP' | 'GREENROOM' | 'WHISPER_GROUP' | null

  // History (never cleared during session)
  sessionGroupHistory: Set<string> // All groups visited in this session

  // Flags
  isInWhisperGroup: boolean
  isInGreenroom: boolean
}
```

### **9.3 Campaign Message Archive**

```ts
interface CampaignMessageArchive {
  campaignId: string
  sessionId: string

  // Retained messages
  messages: ChatMessage[]

  // Session metadata
  startTime: Date
  endTime?: Date

  // Participants
  playerIds: string[]
  dmId: string
  spectatorIds?: string[]
}
```

## **9. Chat Commands**

### **9.1 Overview**

Chat commands are slash-prefixed instructions entered in the chat input. They are parsed client-side before send; the backend validates permissions and processes the action. Commands never appear as raw text in the chat stream — they produce styled output cards, system messages, or toast errors.

**Availability:** DM and Players only. Spectators cannot issue commands but see their output.

### **9.2 UX: Help Popup and Autocomplete**

Two entry points:

1. **Type `/`** in the chat input → a filtered autocomplete command palette appears inline, listing all commands available to the current role. Continued typing narrows the list. Pressing Enter or clicking selects and completes the command.
2. **Click the `[/]` icon** on the left of the chat input → a full help popup opens, showing every available command with its syntax and an example. The popup is role-aware (DM sees DM-only commands; players do not).

The command registry (`shared/types/chatCommands.ts`) is the canonical source of available commands, their syntax, role gates, and descriptions shown in the popup.

### **9.3 Command Registry**

| Command       | Syntax                                 | Who                        | Output                                                                                                   |
| ------------- | -------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------- |
| `/roll`       | `/roll [dice]` e.g. `/roll 1d20+5`     | DM + Players               | Styled roll card in chat (visible to all in room). Supports standard dice notation (`NdX[+/-M]`).        |
| `/me`         | `/me [action]`                         | DM + Players               | Italic emote line: `* {player} draws their sword *`. Styled as IC, scoped to current room.               |
| `/whisper`    | `/whisper @{player} [message]`         | DM + Players               | Shortcut for whisper targeting; same privacy rules as a direct whisper.                                  |
| `/OOC`        | `/OOC [message]`                       | DM + Players               | Forces OOC message styling and tag regardless of the current IC/OOC mode toggle.                         |
| `/dm`         | `/dm [message]`                        | Players                    | Player-to-DM only whisper. Equivalent to whispering `@DM`. DM sees the message; no other players see it. |
| `/take`       | `/take [item] [qty?]`                  | Players (campaign setting) | Transfer item from Party Inventory to own character. Logs to inventory history.                          |
| `/give`       | `/give @{player\|party} [item] [qty?]` | Players                    | Transfer item from own character to target player or Party Inventory.                                    |
| `/loot`       | `/loot [item] [qty?]`                  | DM only                    | Add item to Party Inventory. Generates a loot system message in chat.                                    |
| `/loot-split` | `/loot-split [item] [qty?]`            | DM only                    | Propose a loot distribution card; players accept their share in one click.                               |
| `/drop`       | `/drop [item] [qty?]`                  | DM + Players               | Remove item from own inventory (or party inventory for DM). Logs to inventory history.                   |

Inventory commands are documented fully in `docs/subsystems/INVENTORY-SYSTEM.md`.

### **9.4 Command Parsing Rules**

- Commands must begin with `/` as the first character of the input (leading whitespace is trimmed first).
- The command word is case-insensitive (`/Roll`, `/roll`, `/ROLL` are all valid).
- Arguments after the command word are parsed left-to-right; quantity is always the last argument if present and numeric.
- Unknown command → toast error: `"Unknown command /{word}. Type / to see available commands."` — not posted to chat.
- Permission denied → toast error: `"/{command} is not available to your role."` — not posted to chat.
- Malformed arguments → toast error with the correct syntax hint — not posted to chat.

### **9.5 Implementation Notes**

- Command definitions live in `shared/types/chatCommands.ts` — each entry includes: `name`, `syntax`, `description`, `example`, `roles: Role[]`, `availableInStates: SessionState[]`.
- Frontend `ChatInputParser` detects leading `/`, looks up the command, validates role and state, then either renders the autocomplete palette or dispatches the command action.
- Backend re-validates role and session state before executing any command action (client-side checks are UX only, not security gates).
- `/roll` results are server-side authoritative: the roll is seeded server-side and the result broadcast via `CHAT:MESSAGE_SENT` with `type: 'ROLL'` so all clients see the same value.
- `/me`, `/OOC`, `/whisper`, and `/dm` produce standard chat messages with a `subtype` field (`EMOTE`, `OOC`, `WHISPER`) — they follow all existing visibility and persistence rules for their underlying message type.

## **10. Implementation Notes**

- **Client-side filtering:** Message filtering occurs on the frontend for responsiveness. The visibility algorithm is applied to render only appropriate messages.
- **Server-side enforcement:** Backend validates that users do not receive messages outside their visibility scope. Clients cannot tamper to see hidden messages.
- **Whisper Group volatility:** Whisper Group messages stored in volatile memory only during session. On exit, deleted unless persistence enabled.
- **Greenroom cleanup:** Greenroom messages tagged for cleanup. DM triggers CLEANUP to purge them.
- **Session isolation:** New sessions start fresh. Campaign history is a separate searchable view.
- **Spectator ephemeral:** Spectators do not receive or store persistent message data. Their view is cleared on disconnect.
- **DM transparency:** DM receives all messages with context metadata to enable debugging and session review.

## **11. Session Lifecycle & Message Handling**

### **11.1 Session Start**

1. Session transitions to `ACTIVE`.
2. System message `[Session Started]` persisted to database with `isGlobal: true`.
3. All clients notified via WS `SESSION:STATE_CHANGED` event.
4. Fresh message stream begins; prior session messages accessible only in History panel.

### **11.2 Session Pause**

1. Session transitions to `PAUSED`.
2. System message `[Session Paused]` persisted with `isGlobal: true`.
3. Runtime messages during pause are **not recorded** (off-the-record per pause contract).
4. Chat remains visible but streaming paused.

### **11.3 Session Resume**

1. Session transitions back to `ACTIVE`.
2. System message `[Session Resumed]` persisted with `isGlobal: true`.
3. Message stream resumes; pre-pause messages remain in history.

### **11.4 Session End**

1. Session transitions to `ENDED` or `IDLE`.
2. System message `[Session Ended]` persisted with `isGlobal: true`.
3. All persisted messages archived to PostgreSQL under campaign history.
4. Greenroom messages purged (unless manually archived by DM).
5. Whisper Group messages deleted (unless persistence toggle enabled).
6. Spectator messages cleared; spectators cannot access archive.
