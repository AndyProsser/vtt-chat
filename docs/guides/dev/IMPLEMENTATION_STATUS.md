# Mock Player Implementation Status

Last updated: 2026-05-13 (evening)

## Goal

Use DEV mock players to simulate full multi-player behavior where frontend pathways treat simulated players exactly like real players. Mock identity is backend-internal only.

## Product Contract (Approved Direction)

1. Frontend parity:
   - Mock-generated activity must enter the same state/event paths as real player activity.
   - Role gating, panel visibility, chat behavior, and permissions must execute unchanged.
2. Backend-only mock awareness:
   - Backend may keep internal actor metadata for orchestration.
   - Frontend must not branch by "mock vs real" actor type for runtime behavior.
3. Persistence parity:
   - Data generated by mock actors is stored with the same pipelines and retention rules as equivalent real actor data.
4. Real-user takeover mode:
   - Any connected real user (DM or player) can temporarily assume a mock persona.
   - Enter from player context menu action: "Take Over Player".
   - Exit from Mock Testing panel action: "Return to My User".
   - While takeover is active, the selected player's PLAYER pill color changes to indicate active persona selection.

## Current State

### Implemented

- DEV mock roster seeding and reroll/reset pathways exist on backend.
- Mock testing controls are available in Groups header via the DEV panel.
- Backend takeover session model exists with start/stop/status endpoints.
- Context menu takeover action is wired in room/player UI.
- Mock Testing panel supports "Return to My User".
- Active takeover projects PLAYER pill highlight state.
- Mock speaking/typing/disconnect simulation now runs backend-side and emits canonical WS events.
- Frontend no longer performs local-only mock speaking simulation.

### Not Yet Implemented (Required)

- No blocking implementation gaps identified against this contract.

## Delivery Plan

### Phase 1: Contract-Safe Backend Foundation

1. Introduce backend takeover state per real connection/user.
2. Add endpoint(s) to start/stop takeover.
3. Emit canonical WS events only; no frontend mock-only event types required.
4. Persist simulated actor output through normal chat/presence/session write paths.

### Phase 2: Frontend Takeover UX

1. Add context menu action for eligible actors: "Take Over Player".
2. Add panel action to revert to real identity.
3. Add visual selected-player pill state for active takeover persona.
4. Keep all role/permission checks unchanged so behavior mirrors real players.

### Phase 3: Validation

1. Multi-tab test: DM + real player + simulated players + takeover handoff.
2. Verify chats, notes, groups, role-based panel gating during takeover.
3. Verify persistence: mock-generated data survives refresh/history hydration exactly like real data.
4. Verify no frontend-only mock branching remains in runtime pathways.
