SECTION 7 — STATE RECOVERY
████████████████████████████████████████████████████████████████████████████████

On reconnect:
 1. Transport reconnects with backoff
 2. Server re-associates authenticated connection
 3. Server may replay recent session WS events from Redis using reconnect cursor (`lastEventId`)
 4. Frontend refreshes room/presence/audio state via APIs
 5. Store replaces topology snapshots and resumes WS-driven updates

Multi-device recovery invariants:
 - WS auth includes `deviceSessionId` and `deviceClass` for each connected device.
 - One active mic device per user is authoritative; siblings hard-unpublish on ownership changes.
 - Transfer policy force-disconnects the previous device and returns it to campaign shell.
 - LiveKit webhook signals are reconciled with backend runtime state during recovery.

Current shipped note:
   No single `system.state.hydrate` event is shipped yet.
   Full cross-domain hydrate/event replay remains planned architecture.
   Lobby peak-concurrency metric is backend-derived from telemetry connection-state events
   over a rolling 24h window (authoritative platform status source).
   Offline campaign workspace exposes role-routed settings surfaces (DM campaign settings,
   player character settings, spectator read-only).
   Session shell helpers are being decomposed out of `Workspaces.tsx` into co-located
   modules (`workspaces.types.ts`, `workspaces.utils.ts`, `workspaces.settings.ts`)
   so orchestration stays in the component while pure helpers and normalization logic live
   beside it.
   Frontend screen ownership is now normalized by route/workspace:
   `components/auth`, `components/guest`, `components/watch`, `components/app`.
   Main app workspaces live under
   `components/app/workspaces/{lobby,editor,session}`.
   Shared panels and toolbar components for editor/session live under
   `components/workspaces/shared/{panels,toolbar}`.
   `components/workspaces/shared/toolbar` now holds the toolbar shells, workspace-specific
   toolbar variants, and toolbar visual subcomponents such as the invite popover.
   Shared panel extensions now include reusable player-settings helpers under
   `components/workspaces/shared/panels`, including avatar upload/crop and manual
   handout-publish destination dialogs used by the right rail.
   Toolbar types live in `frontend/src/types`, toolbar constants live in
   `frontend/src/constants`, and toolbar hooks live in `frontend/src/hooks`.
   Room movement / whisper hooks now live in `frontend/src/hooks/session`, campaign
   panel props live in `frontend/src/types`, and party mock-data generators live in
   `frontend/src/utils` instead of component folders.
   `components/workspaces/editor` is edit-flow owned.
   `components/workspaces/session` is launch/runtime owned.
   Within session workspace, the right-rail groups overview is isolated from the left
   voice-groups surface: `GroupsPanel.session.tsx` + `GroupCard.session.tsx` own the
   right-side room overview and its dedicated CSS lives in
   `frontend/src/styles/components/workspaces/session/GroupsPanel.session.css`.
