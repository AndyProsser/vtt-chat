SECTION 7 — STATE RECOVERY
████████████████████████████████████████████████████████████████████████████████

On reconnect:
 1. Transport reconnects with backoff
 2. Server re-associates authenticated connection
 3. Server may replay recent session WS events from Redis using reconnect cursor (`lastEventId`)
 4. Frontend refreshes room/presence/audio state via APIs
 5. Store replaces topology snapshots and resumes WS-driven updates

Current shipped note:
   No single `system.state.hydrate` event is shipped yet.
   Full cross-domain hydrate/event replay remains planned architecture.
