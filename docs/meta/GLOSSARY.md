# Glossary

This glossary defines the core terminology used throughout the VTT‑Chat platform.
It exists to ensure that all contributors — developers, designers, DM tool authors, and AI assistants — share a consistent vocabulary.

Terms are grouped by conceptual domain for clarity.

---

## 1. Core Concepts

### **Actor**

Any entity that can trigger an event.
Includes: Player, DM, Spectator, System.

### **Capability**

A discrete permission that determines what an actor can do.
Used in the Permissions Matrix.

### **Event**

An immutable, declarative message describing something that happened in the system.

### **Reducer**

A pure function that transforms state based on an event.

### **State Store**

The canonical client‑side state container (Zustand).

### **Session**

A running instance of a tabletop game.
Has lifecycle states: _idle → active → paused → ended_.

### **Subsystem**

A functional domain of the platform (Chat, Notes, Audio, Presence, etc.).

---

## 2. Roles & Identity

### **DM (Dungeon Master)**

The table authority.
Has full control over session state, audio, moderation, and visibility.

### **Player**

A participant with character‑level interactions.

### **Spectator**

A read‑only observer with no ability to affect state.

### **System**

A non‑human actor used for automated events and internal transitions.

### **Persona**

A UX‑level representation of a user type (DM, Player, Spectator).

---

## 3. Messaging & Communication

### **IC (In‑Character) Message**

A message spoken as the character.

### **OOC (Out‑of‑Character) Message**

A message spoken as the player.

### **Whisper**

A private message between two actors.

### **System Message**

A message generated by the system (e.g., “Player joined”).

---

## 4. Notes & Knowledge

### **Private Note**

A note visible only to the creator.

### **Shared Note**

A note visible to multiple actors.

### **Note Visibility**

The rules determining who can see a note.

---

## 5. Audio & Effects

### **Audio Graph**

The WebAudio node graph used to route and process sound.

### **Preset**

A saved configuration of audio effects.

### **Effect Trigger**

An event that plays a sound or applies an effect.

---

## 6. Presence & Identity State

### **Presence**

A user’s real‑time status (online, typing, speaking, idle).

### **Avatar**

The visual representation of a user.

### **Presence Override**

A DM‑level action that forces a presence state.

---

## 7. Extension & VTT Integration

### **Overlay**

The UI layer injected into a third‑party VTT.

### **VTT (Virtual Tabletop)**

Any external platform the extension integrates with (Foundry, Roll20, etc.).

### **Extension Bridge**

The communication layer between the browser extension and the core app.

### **VTT Action**

A command sent from the extension to the VTT (e.g., ping map, open sheet).

---

## 8. Architecture & Event Model

### **Event Bus**

The unidirectional pipeline through which all events flow.

### **Event Domain**

A namespace grouping related events (chat, notes, audio, etc.).

### **Event Validation**

The process of checking schema, permissions, and payload safety.

### **Transport**

The mechanism used to deliver events (WebSocket, extension bridge, local dispatch).

### **State Recovery**

The process of reconstructing client state after reconnecting.

---

## 9. UI & Frontend Architecture

### **Component Tree**

The hierarchical structure of React components.

### **Component Interface**

The public API of a React component (props, events, selectors).

### **Wireframe**

A low‑fidelity representation of UI layout.

### **Motion Spec**

Rules governing animation, transitions, and timing.

---

## 10. Operations & Deployment

### **Telemetry**

Analytics and logging used to monitor system health.

### **Backup**

A snapshot of persistent data.

### **Restore**

Rehydrating the system from a backup.

### **Environment**

A deployment context (local, staging, production).

---

## 11. AI Context

### **AI Context Document**

A file providing structured guidance to AI tools for consistent output.

### **AI Persona**

A defined behaviour profile for AI assistants interacting with the project.

---

## 12. Miscellaneous

### **Canonical State**

The authoritative version of the client state.

### **Hydration**

Loading initial state into the client after connection.

### **Diff**

A minimal representation of state changes.

---

This glossary is a living document.
Contributors should update it whenever new terminology is introduced.
